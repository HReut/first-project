# Opa! Tulik Maintainer

You are the specialized agent for this repository.

## When to use this agent
Use this agent when working on the expense tracker app in this workspace, especially for:
- UI and view changes in the client-side SPA
- Data-layer updates in the repositories and local-store fallback
- Supabase integration and schema-related changes
- Styling and layout updates in the single stylesheet
- TypeScript fixes and small refactors that preserve the existing architecture

## Project context
- This is a Vite + TypeScript single-page application with no React/Vue framework.
- The app uses hand-rolled DOM rendering via template strings and view modules in src/components/views.
- State is centralized through the lightweight store in src/state/store.ts.
- The app supports both Supabase-backed data and a localStorage fallback, so it must remain usable without environment setup.
- The project guidance in CLAUDE.md is the source of truth for repo-specific behavior.

## Working conventions
- Read CLAUDE.md first before making changes.
- Preserve the existing architecture instead of introducing frameworks, new state libraries, or broad rewrites.
- Keep the dual-mode data layer intact: changes should work with Supabase when configured and with the local fallback when not configured.
- Follow the repo conventions:
  - use explicit .ts imports
  - use type-only imports where appropriate
  - keep TypeScript syntax compatible with the current config
  - avoid unused imports and unused parameters
- If you change the data shape or schema, update both the Supabase migration and the local mock seed so they stay in sync.
- Prefer small, targeted edits that match the existing patterns in the surrounding files.

## Preferred areas of focus
- src/components for views, shared UI, and DOM-driven behavior
- src/data for repositories and local data persistence
- src/types and src/types/database.ts for domain and database shapes
- src/utils for insights, filters, formatting, and budget logic
- src/style.css for styling changes
- src/lib/supabaseClient.ts and supabase/migrations for Supabase-related work

## Avoid
- Introducing React, Vue, or another framework
- Replacing the current store or view architecture with a new abstraction
- Breaking the local-first zero-setup experience
- Making styling changes that ignore the existing color system and contrast constraints

## Verification
After implementing changes, verify them with:
- npm run build

If a change affects behavior visibly, also check the app locally with npm run dev when possible.
